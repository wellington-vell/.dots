# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## What this is

A NixOS flake organized around the [Dendritic pattern](https://github.com/mightyiam/dendritic),
powered by [flake-parts](https://flake.parts/) and [import-tree](https://github.com/denful/import-tree).

The core idea: **every Nix file except entry points is a flake-parts module** (a "feature").
Each file implements one feature across every configuration it applies to. Lower-level
configurations (NixOS, home-manager, ...) are stored as `deferredModule` values under the
`flake.modules.<class>.<name>` option, and files merge under shared names.

There are no manual import lists. `imports.import-tree ./modules` recursively loads every
`.nix` file under `modules/` as a flake-parts module, so files can be added, removed,
renamed, or moved freely. Files/dirs starting with `_` are ignored by import-tree (used as
an opt-out when needed).

## Layout

```
flake.nix                              entry point: flake-parts + import-tree
flake.lock
config/hypr/hyprland.lua               Hyprland Lua config (wired via Nix store --config)
modules/                               every *.nix here is a flake-parts module
├── flake-parts.nix                    imports flake-parts.flakeModules.modules
├── system/                            basic system modules (audio, network, drivers, …)
│   ├── audio/default.nix              → flake.modules.nixos.base
│   ├── network/default.nix            → base
│   ├── hardware/default.nix           → base (+ /etc/nixos/hardware-configuration.nix)
│   ├── boot/, nix/, locale/, users/, packages/, state/, git/
│   ├── desktop/default.nix            attr: imports hyprland, noctalia, apps, …
│   └── drivers/nvidia.nix             host-opt-in GPU stack
├── features/                          named desktop/app features (not auto-on base)
│   ├── hyprland/default.nix
│   ├── noctalia/, firefox/, discord/, gaming/, …
│   └── editors/, terminal/, keyring/
└── hosts/
    └── well.nix                       composition + nixosConfigurations.well
```

`modules/system/` holds machine/OS plumbing (PipeWire, NetworkManager, boot, drivers).
`modules/features/` holds opt-in desktop/app features composed by `system/desktop`.

### Entry points (exceptions to the pattern)

- `flake.nix` — flake entry point, must stay as-is.
- `/etc/nixos/hardware-configuration.nix` — machine-local, generated by
  `nixos-generate-config`. Imported by `modules/system/hardware/default.nix` into `base`.
  Not in the repo. Because the path is absolute and outside the flake, rebuilds and checks
  need `--impure`.

## How modules merge

System commons under `modules/system/` contribute to `flake.modules.nixos.base`. Desktop
apps contribute to **named** deferred modules (`hyprland`, `gaming`, …).
`modules/system/desktop/default.nix` composes those names; hosts opt in by listing `base`,
`desktop`, `nvidia`, etc. in `nixosSystem`.

```nix
# modules/system/boot/default.nix — merges into shared base
{
  flake.modules.nixos.base =
    { pkgs, ... }:
    {
      boot.loader.systemd-boot.enable = true;
      boot.kernelPackages = pkgs.linuxPackages;
    };
}
```

```nix
# modules/features/firefox/default.nix — named feature; included only via desktop
{
  flake.modules.nixos.firefox = {
    programs.firefox.enable = true;
  };
}
```

Note the `{ pkgs, ... }:` — this is a *NixOS* module (the deferred module body), evaluated in
the NixOS context, not at the flake-parts top level. Do not reference `pkgs` in the outer
flake-parts module; it is not available there.

### Hosts

A host file composes features and exposes a flake output. Hardware comes from the machine
via `base`; do not commit per-host `hardware-configuration.nix` files.

```nix
# modules/hosts/well.nix
{
  config,
  inputs,
  ...
}:
{
  flake.modules.nixos.well = {
    networking.hostName = "well";
  };

  flake.nixosConfigurations.well = inputs.nixpkgs.lib.nixosSystem {
    modules = with config.flake.modules.nixos; [
      base
      desktop
      nvidia
      well
    ];
  };
}
```

### Hyprland config

`config/hypr/hyprland.lua` stays in the repo. `modules/features/hyprland/default.nix` wraps
the Hyprland package with `--config` pointing at that store path. Do not copy configs into
`~/.config/hypr` via activation scripts.

### Audio

`modules/system/audio/default.nix` enables PipeWire / WirePlumber on `base`. Do not add
session-start shell scripts for default sinks; use WirePlumber drop-ins if device selection
is needed.

## Rules of thumb

- **One feature per file.** If a file grows, split it into more feature files, don't bolt on
  unrelated settings.
- **Importing a module should enable the feature.** Prefer defining the enabling config
  directly over adding `enable` options (see the the dendritic "anti-patterns" doc).
- **Share values via the top-level config**, never via `specialArgs` pass-through.
- **Name files after the feature**, not after the config class (`nix.nix`, not
  `nixos/nix-configuration.nix`). Paths are free-form; only the feature they express matters.
- **Put host-specific stacks in named modules** (`nvidia` under `system/drivers/`), not in
  `base`.

## Common tasks

### Add a system package

Edit `modules/system/packages/default.nix`, appending to the `environment.systemPackages`
list. Rebuild with `sudo nixos-rebuild switch --impure --flake .#well`.

### Add a new shared system feature

1. Create `modules/system/<feature>/default.nix` defining
   `flake.modules.nixos.base = { ... };`.
   import-tree picks it up automatically (applies to every host that includes `base`).

### Add a new desktop feature

1. Create `modules/features/<feature>/default.nix` defining
   `flake.modules.nixos.<feature> = { ... };`.
2. Add `<feature>` to the `imports` list in `modules/system/desktop/default.nix`
   (or to a specific host).

### Add a new host

1. Create `modules/hosts/<name>.nix` modeled on `well.nix`.
2. On the machine: ensure `/etc/nixos/hardware-configuration.nix` exists
   (`sudo nixos-generate-config`).
3. Compose `base` plus whatever named modules that host needs (`desktop`, `nvidia`, …).

### Disable a feature temporarily

Prefix the file or directory with `_` (e.g. `_glyphs.nix`) — import-tree ignores it.

## Verification

```console
nix flake check --impure
nix flake show
sudo nixos-rebuild switch --impure --flake .#well
```

`nix flake check` may print `unknown flake output 'modules'`; that is expected — the
dendritic `flake.modules` grouping also gets published as a flake output. Harmless.
